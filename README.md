# 发货自动化控制台

统一操作 `login-auto`（登录与前置准备）、`shipping-auto`（创建发货单）和 `packing-auto`（装箱发货）。
提供快照、测试演练、正式执行、实时日志、截图预览和日志下载。

## 启动

需要 Node.js 18+、本机已安装 Google Chrome。

```bash
# 在项目根目录，首次安装两套脚本的 playwright-core 依赖
npm run setup

# 启动 Web 控制台（Web 本身没有第三方依赖）
npm start
```

打开 <http://127.0.0.1:3000>。首次使用先在「登录与前置准备」填写账号密码，点击「登录并打开页面」。
关闭服务用 Ctrl+C。修改端口可设置环境变量 `PORT`，例如 macOS/Linux：`PORT=3100 npm start`；PowerShell：`$env:PORT=3100; npm start`。

## 操作含义

「登录与前置准备」使用独立脚本 `login-auto/index.js`。填写手机号或子账号邮箱、密码并勾选登录协议授权后，脚本会自动从扫码页切换到对应登录方式，填写并提交；验证码、店铺选择等步骤可在 Chrome 中手动完成。登录或页面加载失败时会保留窗口供手动继续。会话没有自动结束时间，也不会在登录成功后自动启动发货；请手动关闭 Chrome 或点击「停止准备」，释放登录配置后再运行后续流程。刷新或关闭控制台网页不会结束会话。

已保存浏览器登录信息时，账号密码框隐藏，按钮变为「打开页面」。只有观察到登录成功后才保存登录标记，Chrome 自动创建的 Cookie 数据库不算已登录；登录失效时会清除标记，结束准备后可重新填写账号密码。账号密码仅通过 IPC 交给本次登录子进程，不写入命令行、控制台状态或运行日志；后续复用 Chrome 配置保存的登录状态。

控制台会在输入、自动填充变更和提交时，将账号密码缓存到当前浏览器的 `localStorage`，刷新或重新打开同一地址后自动恢复。提交、运行结束和登录成功都不会清空这些输入。缓存只保存在当前浏览器、当前控制台地址；「清除登录信息」会同时删除缓存和清空输入框。登录协议授权不写入缓存。

三个脚本均使用 Playwright 的 `launchPersistentContext`、`channel: chrome` 和有界面模式启动本机 Google Chrome，统一使用 `shipping-auto/.pw-profile`，无需选择登录配置。每次任务各自启动 Chrome 窗口，登录状态共用；先结束登录准备以释放目录，再执行创建发货单或装箱。`node login-auto/index.js` 可单独打开准备会话；`node login-auto/index.js --probe` 按同样方式启动 Chrome，抓取扫码、手机号、邮箱登录页的截图和字段 JSON 到 `login-auto/shots/`，不输入账号或提交登录，完成后继续留窗。

| 流程 | 快照 | 测试 | 正式执行 |
| --- | --- | --- | --- |
| 创建发货单 | 执行 `probe`，抓取页面 DOM 和截图 | 执行 `--dry --debug --max-rounds=1`，验证页面操作，不提交数量和发货单 | 按指定数量与轮数真实修改、创建发货单 |
| 装箱发货 | 执行 `probe`，会勾选首行、打开抽屉并检查日期时间面板，不确认发货 | 执行 `--dry --debug --max-rounds=1`，演练流程，不确认发货 | 按箱数与轮数逐单确认发货 |

装箱自动复用前置登录保存的 `shipping-auto/.pw-profile` 登录状态。正式执行的轮数默认 200，测试固定只演练 1 轮。脚本步骤失败时仍可能以退出码 0 结束，因此页面显示 `EXIT 0` 只代表进程正常退出，业务结果请核对日志和截图。

装箱脚本原有 `--dry` 会跳过「批量装箱发货」的真实点击，因此未打开抽屉时可能在等待抽屉阶段结束；这是现有脚本的演练范围。需要检查抽屉、日期和时间面板时使用「快照」。

执行过程中可点击日志区的「停止执行」，其他按钮和输入项禁用；停止会等待脚本和浏览器退出，已提交的业务操作不会撤销。后端全局锁同时拦截其他标签页的执行请求。页面刷新、关闭或短暂断网不终止正在运行的任务；SSE 重连后恢复当前任务和最近日志。任务正常结束、异常退出或启动失败后自动解除锁定。

页面展示最近 8 张截图，运行时每 5 秒更新。截图保存在各脚本 `shots/`，可点击查看原图。最新任务的完整日志可下载，所有任务日志保存在根目录 `.web-runs/*.log`；页面仅保留有限的最近输出，服务重启后不恢复运行状态和历史展示。不要在运行中重启服务；关闭服务会向脚本发送终止信号，并尽力关闭其浏览器。

控制台仅绑定本机 `127.0.0.1`，用于运行当前电脑上的脚本。Web 调用的快照、测试和正式执行会在完成后关闭浏览器，释放登录目录；登录准备和主动快照会持续保留窗口，直到用户关闭或停止。原有 `shipping-auto` 命令行行为保持不变，新增 `--close-browser` 参数可启用相同清理逻辑。

## 开发与验证

```bash
npm run dev
npm test
npm run test:login  # 用本机 Chrome 对本地模拟登录页验证手机号/邮箱自动切换与提交
```

测试使用模拟子进程验证日志、互斥、重连与错误恢复，不连接商家后台，也不执行真实订单。

```text
web/
  server.js          Node HTTP 服务、任务调度、SSE、日志和截图接口
  server.test.js     使用 node:test 的集成测试
  public/            原生 HTML / CSS / JavaScript 控制台
shipping-auto/       原有创建发货单脚本及 docs.md
packing-auto/        原有装箱发货脚本及 docs.md
login-auto/          独立登录与前置准备脚本，复用现有 Playwright 依赖
AGENT.md             项目与代理开发说明
```

页面所有「清除登录信息」按钮操作同一份本地 Chrome 登录配置，清除后三个流程都需重新登录。清除前请关闭使用该配置的 Chrome 窗口，任务运行中不可清除。

## 主动快照（多步动态页面）

点击对应流程的「主动快照」，等待日志提示就绪，在 Chrome 中登录并手动操作到目标步骤。每次节点渲染完成后点击日志区的「抓取当前页面」，可以连续抓取弹窗、下拉面板和下一步页面。该模式只打开流程入口，不自动执行发货操作；手动操作仍按商家后台自身行为生效。

每次保存全部打开标签页的 PNG 和同名 JSON，JSON 包含页面 URL、抓取时间及各 frame 的当前 HTML。页面快照区可预览截图、下载 DOM，文件也保存在对应脚本的 `shots/` 下。跨多个页面的抓取按顺序执行，建议抓取期间暂停手动操作，完成后再进入下一步。点击「结束快照」关闭浏览器并释放任务锁；刷新控制台后仍可继续抓取。
